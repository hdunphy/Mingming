## HEADLINES

- **skoll_v1 is NOT dead in 1v1.** `target: "ALLY"` includes SELF — `ConditionValidator` only checks side membership (`src/engine/core/ConditionValidator.ts:46-48`). Skoll taking an enemy hit procs his own Strengthened. It also procs on *non-damaging* enemy actions (onPostDamage fires per action, damage or not: `src/engine/battleReducer.ts:389,559`). The hand-audit claim "dead in 1v1" is **wrong**; the description ("an allied Mingming") is what's wrong.
- **huldra_v2 BARK_SHIELD_OS never fires for the player side.** The custom hook requires `state.turn === 1` at onTurnStart (`src/engine/core/CustomFirmware.ts:150`), but battles start in `phase: 'ACTION'` with no initial pre-turn (`src/engine/data/battleFactories.ts:323-325`); the player's first onTurnStart is turn 2 (`src/engine/battleReducer.ts:783`). Enemy-side Huldra gets the shield; player-side never does. Also a units bug: `stacks = floor(maxHp*0.5)` but BarkShield stacks are *percent of maxHp* (`src/engine/StatusBehaviors.ts:411-424`), so shield size scales quadratically with maxHp.
- **sleipnir_v2 is an infinite loop:** `hoof_strike` is an Air Attack token, and WAR_STEED_OS has no `isToken: false` guard (`src/engine/data/lib/hooks.json:669-692`, contrast `echo_chamber` at :400), so each free token play generates another token — unbounded 0-cost attacks in one turn.
- **draugr_v2 is dead against MOVES enemies** (cost hooks only run inside `handlePlayProgram`, `src/engine/battleReducer.ts:232`; intents pay no cost) and near-dead otherwise: `sourceDebuffCount` counts *distinct* negative status types (`src/engine/core/ConditionValidator.ts:96-102`) and Draugr's whole baseDeck applies only Weakened.
- **Confirmed dead-as-audited:** kraken_v2 (deck max cost 2; also only 2 of the 5 nominal pool matches actually deal card damage), hraesvelgr_v1 (zero DISCARD/FORCE_DISCARD cards and zero `discardEffect` fields in the 111-card pool; executors exist but nothing uses them), skoll_v2 (only Burn source in deck is self-targeted `all_in`), draugr_v1 (only sleep applier in pool is Nature `sleep_powder`; no revive mechanic exists at all).
- **Definitive 1v1-dead list is exactly three:** valkyrie_v1 (custom code explicitly excludes self, `CustomFirmware.ts:113`), valkyrie_v2 (`ALIVE_ALLIES` excludes owner → multiplier ×1.0, `src/engine/core/HookFactory.ts:110-114`), nidhoggr_v2 (only faints in 1v1 are self — hook filtered out, `src/engine/resolutionEngine.ts:288` — or the sole enemy, which ends the battle). huldra_v1 and audhumbla_v2 both work in 1v1.
- **All five "empty-hooks" variants have real CustomFirmware implementations** merged by `src/engine/data/firmwareRegistry.ts:45-47`; none are vaporware. But two data hooks over-fire: jormungandr_v2 heals at the end of *every* side's turn (× active-side unit count) — no `when` clause at all (`hooks.json:545-558`); kraken_v1 has no `source` condition and procs on *any* non-natural draw by either side (`hooks.json:100-121`).
- **Prior art (2026-08-05):** `OSGapClosures.test.ts` shows 9 gap-closure items already landed (overheal counter plumbing, fafnir_v1 recoil timing, valkyrie_v1 real statuses, audhumbla_v1 exact-3rd counting, per-unit OWNER-scoped counters, hraesvelgr_v2 dead-data removal, intent side-buff fix, gullinbursti_v1 prime semantics, ymir_v2 card cap) — registry/data changes are already made, not planned.

## 1. HOOK TRUTH — implemented behavior per variant

Merge model (`src/engine/data/firmwareRegistry.ts:37-59`): JSON hooks are compiled by `HookFactory.createHook` and concatenated with `CustomFirmware[key]`; every hook is `registerHook`ed by id. At runtime, hooks are collected per entity as a **Set of ids** (`src/engine/resolutionEngine.ts:292-296`), so a JSON hook and a custom hook sharing an id (fafnir_v2, see below) deduplicate to whichever registered last (⚠ HookRegistry.ts not staged; assumed last-write-wins map).

Condition semantics used below (`src/engine/core/ConditionValidator.ts`):
- `source/target: SELF` = identity match with owner (:34, :43). `ALLY` = **same side as owner, INCLUDING owner** (:38, :46-48). `OPPONENT` = other side. Unrecognized values (e.g. `"ANY"`) match no branch → always pass.
- `actionType: 'ATTACK'` = the program has *any* ATTACK action (:52-56) — self-hit attacks (`glass_cannon`, `dark_pact`) count.
- `baseCost` compares the program's printed `baseCost`, not the effective/paid cost (:60-72).
- `isNaturalDraw` is true only for turn-start hand refills (`src/engine/resolutionEngine.ts:452, battleReducer.ts:836-856`); all DRAW-action/hook draws pass `false`.
- `programCategoryIn/Not` compare `program.category`; `programAppliesStatus` = program has a STATUS action (:83-93).
- `sourceDebuffCount` counts distinct negative status *entries* on `context.source` from the list Burn/Poison/Asleep/Weakened/Dazed/Stunned/Bleed (:9, :96-102).
- `counter` keys are OWNER-scoped by default (`key:ownerId`, `src/engine/core/HookTypes.ts:11-13`).
- `onStatusApplied` fires even when duality cancellation eats all stacks (`src/engine/effectHandlers.ts:500-514` runs unconditionally after apply).
- `onStatusRemoved` fires on: wake-by-damage (`effectHandlers.ts:234-246`), cleanse (:555-568), natural end-turn expiry (`battleReducer.ts:743-755`), forced REMOVE_STATUS (:1040-1059).
- `onTurnEnd`/`onTurnStart` are invoked once per alive active-side entity with `context.source = that entity` (`battleReducer.ts:764-773, 823-833`); a hook without a `source: SELF`-style guard fires on every invocation.

## 3. 1v1-TESTABILITY — definitive list

**Cannot produce a gameplay-relevant trigger in 1v1, regardless of deck (3 variants):**

1. **valkyrie_v1 VALHALLA_UPLINK** — custom guard `context.target && context.target.id !== owner.id` plus same-side check (`src/engine/core/CustomFirmware.ts:113-118`). In 1v1 the only same-side unit is Valkyrie herself, which is explicitly excluded (and `OSGapClosures.test.ts:172-182` pins self-exclusion as intended). No deck fixes this.
2. **valkyrie_v2 EINHERJAR_RALLY** — `scaling: 'ALIVE_ALLIES'` resolves to `party.filter(e => e.currentHp > 0 && e.id !== owner.id).length` (`src/engine/core/HookFactory.ts:110-114`), i.e. 0 in 1v1; the modifier becomes `1 + (1.1−1)×0 = ×1.0` (`HookFactory.ts:66`). The hook "fires" but is arithmetically inert.
3. **nidhoggr_v2 FALLEN_FEAST_OS** — onUnitFainted fires from `checkDefeat` (`src/engine/effectHandlers.ts:305-314`). In 1v1: (a) if Nidhoggr faints, the hook never runs for him — hook collection filters `currentHp > 0` (`src/engine/resolutionEngine.ts:288`); (b) if the sole enemy faints, the hook technically executes (a state-level test could observe +3/+3), but the battle is over (`battleReducer.ts:186-189` blocks further plays) so the buff can never be used. Gameplay-dead; sim-dead for any win-rate metric.

**Explicitly cleared (candidates that DO work in 1v1):**

- **skoll_v1** — works: `target: 'ALLY'` is a side check that includes the owner (`ConditionValidator.ts:46-48`); Skoll being hit (or even debuffed) by the enemy procs it.
- **huldra_v1** — works: same ALLY-includes-self semantics on the *target* of her own status application; every self-buff (e.g. `overgrowth` on self) mirrors Weakened onto the enemy.
- **audhumbla_v2** — works: overheal is reachable in 1v1 (heal self at/near full HP; `effectHandlers.ts:333-336` records `last_overheal` from intended-vs-max overflow; proven single-unit in `OSGapClosures.test.ts:82-104`).

**Conditionally dead (not deck-fixable within current rules, but not strictly 1v1-logic):**

- **huldra_v2** — dead for the player side in every battle shape (turn-guard vs. no initial pre-turn; see §1 row 20). Testable 1v1 only by putting Huldra on the *enemy* side, or by seeding `turn: 1` state and cycling to the enemy turn.
- **draugr_v2** — dead vs MOVES enemies (default mode); 1v1-testable only with `enemyMode: 'CARDS'` plus an enemy carrying ≥2 distinct debuff types.
- **hraesvelgr_v1** — dead everywhere until a discard-outlet card exists (DEAD-IN-POOL, not 1v1-specific).
- **skoll_v2 / draugr_v1 / kraken_v2** — 1v1-mechanically fine; dead only through deck/pool composition (§2).
