## Traps on this machine

- **Git cannot unlink its own lock and temp files** through the agent's shell. After every git command, move `.git/*.lock`, `.git/objects/maintenance.lock`, `.git/next-index-*.lock` and `.git/objects/*/tmp_obj_*` into `_to_delete/git-locks/` (gitignored). `_to_delete/unlock.sh` does all of it. Leave a lock alone if it is less than a minute old: another agent may be committing.
- **Switching branches can leave files behind**, for the same reason: files the target branch doesn't have stay as untracked files, and files it changes may keep their old content while `git status` looks clean. After a switch, compare against the branch tip (`git diff --stat HEAD`, and `git cat-file --filters HEAD:<path>` to rewrite a stale file in place) before building.
- **Git cannot rename over an existing file here either**, so `git update-ref`, `git commit` and index writes fail with "Operation not permitted" and leave a `.lock`. 185 built its commits with plumbing (a private `GIT_INDEX_FILE`, `git hash-object -w --path=<file>`, `commit-tree`), wrote the branch ref and `.git/index` in place (`cat new > file`), and parked the leftovers in `_to_delete/git-locks/`.
- **Stage explicit paths only** (`git commit -- <paths>`). More than one agent shares this working tree.
- **Merging to `main` can publish the game**, to the restricted itch.io page (181d, `301bb63`; GitHub Pages no longer gets a deploy). The "Deploy to itch.io" workflow runs on every push to `main` and publishes only when the tag `v<version>` does not exist yet, then creates it (181e); so a merge that bumps the version in `package.json` is a release. Its "Run workflow" button (`workflow_dispatch`, any branch) publishes a pre-release build and creates no tag. Until Henry sets `BUTLER_API_KEY` and the real `ITCH_TARGET`, the publish step fails on `CHANGE-ME/mingming`.
- Local git thinks the repo's default branch is `steam-release-prep`. Check a pull request's base branch before merging.

- **Agent worktrees (2026-10-08).** They live in `.claude/worktrees/agent-<id>`. A new one can start on an OLD commit: run `git merge --ff-only first-impressions` inside it first. Many have `node_modules` as a directory JUNCTION to the main folder's. BEFORE removing a worktree, run `cmd /c rmdir <worktree>
ode_modules` (that removes the link only); never delete through it. Then `git worktree unlock <path>` and `git worktree remove --force <path>`. Windows sometimes refuses to delete the now-empty folder ("Permission denied": a process holds it); retry later, it holds no work.
- **The orchestrator's `report` tool failed for every agent** ("no tool.call hook answered"); the agents sent their reports as messages instead. Each branch is named `worktree-agent-<id>` and stays after its worktree is removed.
- **Line endings.** The repo stores LF; the working tree is CRLF except `*.sh`, `*.mjs` and the two playtest briefs (LF, pinned in `.gitattributes`). After an attribute change a file can show as modified with identical content: `git add -- <those files>` clears it without changing anything.
- **PowerShell writes a byte-order mark** into a commit-message file, so a commit subject can start with an invisible character (`f04a6062` does). Use `git commit -m` or a UTF-8 file without a BOM.
- **`vitest run <path>` also matches copies inside `.claude/worktrees`.** Use `--dir src`. The stop hook that lists "uncommitted files" is usually looking at another agent's worktree, not the main folder: check `git worktree list` and `git status` before acting.
