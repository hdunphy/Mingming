# Elite nodes: one harder fight with the Driver as visible stakes; alpha and ambush (ticket 17)

- Type: wayfinder:task
- Status: closed

- Blocked by: [11](11-encounter-flow.md), [16](16-drivers.md)

## Deliverable

Elite = ONE harder fight, the Driver reward visible on the map node before you commit. Plus the two designed asymmetric exceptions: ALPHA (one overtuned elite-frame wild vs your full team; guards a guaranteed blueprint; uses the `maxHp × 1.5` boss-frame pattern already in `battleFactories`) and AMBUSH (their 3 vs your 2, marked high-risk). Elite team construction: a curated pick from the tuned decks, never stat inflation (difficulty = tiers, not scaling).

## Done when

The three node types are generated by ticket 07's mix, fight correctly, and pay their stakes; map icons distinguish them.

## Resolution

**Closed 2026-09-12, RE-SCOPED BY HENRY the same day.** On reading the audit — *"the elites exist"* —
he ruled: *"For now just add the driver reward, ignore the overtuned on the alpha. Add to the
ambush's markings. Ambushes should also offer a driver since right now it is harder than the elites,
but it's 'bonus' content."* So this ticket shipped the Driver as the stakes of **elites AND ambushes**,
the ambush's high-risk marking, and nothing on the alpha. Suite **177 files / 2,372 tests**, all gates
green.

### What already existed, which is why this was small

Tickets 07 / 11 / 60 / 61 had built the node kinds themselves: `elite`, `alpha` and `ambush` are rolled
into the graph, each has its own icon, an elite fights with a tuned deck + OS + lite AI at the player's
own IV roll, an alpha is one enemy vs the full party, an ambush is the party +1 (cap 3), the alpha's
guaranteed blueprint is ruled and implemented, and the region's final elite carries the gym's Driver
as an enemy passive (68 ruling 4). What no ticket had built was the PLAYER's Driver reaching the player:
ticket 16 made the eight and, having removed the gym-clear relic pick, left `addDriver` with no caller.

### The stake is decided at run creation, and the map says it

`src/engine/run/driverStakes.ts` — `assignDriverStakes(nodes, biomes, seed)`, called from `createRun`,
stamps **`IRegionNode.driverStake`** onto every elite and ambush. Rolled ONCE off a fresh
`SeedStream(seed).fork('driver-stakes')` (the scout's pattern), so no existing graph's ids, kinds or
edges moved — pinned in `driverStakes.test.ts` and in `createRun.test.ts`'s graph-equality test, which
now strips the stamp before comparing. The pool is the **named seven plus this run's own Element
Drivers** (a Dark Driver in a Fire/Water/Nature run is a dead node — ticket 69's "your elements"
reasoning); gym Drivers never; a seeded shuffle without repeats, so two elites in one run never pay the
same Driver and `addDriver`'s dedupe never swallows a reward. Optional in `RegionNodeSchema` for the
scout's reason: a pre-17 save resumes as it was.

**On the map** (`RegionMap.tsx`): a revealed elite's label reads `Elite, Fire, stakes: FIRST BLOOD, …`
and the node wears a solid violet **stake ring** — the Driver chip's colour, so the map and the battle
bar say "Driver" in one voice (the scout's ring is dashed at the same radius; a node can be both). An
ambush reads **`Ambush, Water, HIGH RISK — they outnumber you, bonus: ANTIVENOM, …`** and its disc is
tinted red (`.rm-node.risk`; the stroke stays the element's). The legend explains both, only in a run
that has a stake to explain. The fog keeps the stake: a fogged node shows shape, not prize.

### The win pays it, on CONTINUE, as a receipt

`BattleArena` reads the current node's `driverStake` (elite/ambush only — `paysDriver`) and carries it
on the bundle as **`IRewardBundle.driver`**; it is READ, never re-rolled, so the report pays exactly
what the map promised. `BattleReport` shows a **DRIVER INSTALLED** block (name + rule text, violet,
`data-testid="reward-driver"`) beside the blueprint flash — a receipt, not a choice. `handleContinue`
dispatches `addDriver` with the cards. Installed on CONTINUE rather than on drop, deliberately: a
Driver is run-scoped, so the crash-safety argument that banks blueprints on drop does not apply.

**Interaction test (ticket 58's rule):** `App.loop.test.tsx` gained *"an ELITE won → the report shows
the Driver the map promised, CONTINUE → the party holds it"* — plants a stake on the first node, reads
`stakes: FIRST BLOOD` off the travel button and the ring off the SVG, wins, sees the receipt, clicks
CONTINUE, and asserts `run.drivers === ['driver_first_blood']`. Plus `RegionMap.test.tsx` (label,
ring, legend, HIGH RISK, bonus wording, fog, nothing-when-no-stakes) and `driverStakes.test.ts`
(kinds, pool, distinctness, determinism, graph untouched, v4 parse + legacy load).
