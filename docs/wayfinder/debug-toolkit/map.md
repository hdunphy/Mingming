# Debug & Testing Toolkit — Wayfinder Map

Label: `wayfinder:map`

**Tracker conventions (local-markdown fallback):** tickets are files in [`tickets/`](tickets/). Each carries `Type` (`wayfinder:research|prototype|grilling|task`), `Status` (`open|closed`), `Assignee` (blank = unclaimed), and `Blocked by` (links). A session claims a ticket by writing its name into `Assignee` before working. The **frontier** is every ticket that is open, unblocked (all Blocked-by closed), and unclaimed. Resolutions are recorded in the ticket's `## Resolution` section on close, and gisted below.

## Destination

A dev-build-only debug toolkit, built and working on the repo: a hidden **Debug tab** (scenario launcher + save/run editor), a **mid-battle debug overlay** (live state manipulation), **JSON scenario files** (composable by hand, exportable from a live battle, replayable), and a **headless batch-sim / balance auditor** that reuses scenario definitions — all tree-shaken out of production builds. Done when at least one real bug and one real balance question have each been driven end-to-end through the toolkit.

## Notes

- **Execution override:** unlike wayfinder's plan-only default, this map carries implementation — build tickets graduate out of the fog as design tickets resolve.
- Domain: React 19 / TypeScript / Vite / Redux Toolkit; headless engine in `src/engine`. Repo conventions: `npx vitest run` + `npx tsc -b` + `npx vite build` before shipping; never commit `package-lock.json`; git lock-sweep before device-side git commands.
- First leg: scenario launcher. UI form: Debug tab + battle overlay (both). Gating: `import.meta.env.DEV` only. Scenarios: JSON files checked into the repo at `src/debug/scenarios/{repro,balance}/<slug>.scenario.json`, with live-battle export.
- **Standing invariant once [Debug gating scaffold](tickets/12-debug-gating-scaffold.md) lands:** nothing outside `src/debug/` may import anything inside it. `src/debug/DebugRoot.tsx` is the only edge, and a post-build marker assertion enforces it.
- Key asset (from the audit): `IBattleState` is pure JSON data, the RNG seed is a plain string in state, and hooks are ID strings resolved against module registries — snapshot/replay is architecturally cheap. The main debt is creation-path nondeterminism and the total absence of dev gating.

## Decisions so far

- [Engine readiness audit](tickets/01-engine-readiness-audit.md) — Engine is snapshot-friendly (pure-JSON state, string seed threaded through reducers, registry-resolved hooks); nondeterminism is confined to battle *creation* (`Date.now`/`Math.random`/`randomUUID` in `battleFactories.ts`); `battleSlice.setBattleState` already injects arbitrary battles; **no dev gating exists anywhere** — Balance/Studio tabs and `window.runSim` ship to players today. Full findings: [research/01-engine-readiness.md](research/01-engine-readiness.md).
- [Scenario schema v1](tickets/02-scenario-schema.md) — **One** zod envelope discriminated on `kind: 'composed' | 'snapshot'` (launcher writes composed, export writes snapshot, sims re-roll seeds only on composed, replay takes either). Drift guard = int `version` + a `registryHash` content stamp over the Mingming/Program/OS registries; mismatch **warns loudly and loads anyway**. The ~9 dropped optionals are handled by one shared `normalizeBattleState()` applied at write, read, *and* diff — a fill class with real defaults, and a strip class where absence is semantically real. Files live at `src/debug/scenarios/{repro,balance}/<slug>.scenario.json`, inside `src/` so `import.meta.glob` bundles them in dev and drops them in prod.
- [Debug gating architecture](tickets/03-debug-gating-architecture.md) — Gate is `import.meta.env.DEV` wrapping a **lazy `DebugRoot`**, and `src/debug/DebugRoot.tsx` is the **single import edge** between game and toolkit, backed by a post-build `__DEBUG_TOOLKIT__` marker assertion. One `DebugRoot` is hoisted **above both App.tsx early returns** and has two presentations — floating (chip + hotkey, works at roster 0 and mid-battle) and docked (the DEV-only Debug tab) — so the early returns are never touched. Balance and Studio move in as panels; `window.runSim` survives as a one-line DEV-only import in `main.tsx`. Dispatch standardizes on `setBattleState` (dead `INITIALIZE_BATTLE` deleted); every god-tool verb is a **pure `(state, args) => IBattleState` function** under `src/debug/`, which keeps debug code out of the slices and makes the command set headlessly testable. No `debugSlice` — debug UI state lives in React context inside `DebugRoot`, so `store.ts` is never edited. Verbs append `[DEBUG]` lines to `state.logs`.
- [Live-manipulation command set](tickets/05-live-manipulation-command-set.md) — Ten v1 verbs (vitals, statuses, add-card-to-hand, set/execute intent, skip turn, insta-kill); deck stacking and AI-pause deferred. **Everything goes through the engine**: three verbs ride existing actions, five new *general-purpose* engine actions are added — which **amends 03 §4** from "no debug code in the reducer" to "no debug-*specific* code". 03's mechanism is untouched: verbs remain pure `(state, args) => IBattleState` functions under `src/debug/` applied via `setBattleState`, now delegating to `battleReducer` directly (a plain function, not a slice) so no `battleSlice` action is needed. Hooks fire **faithfully** and the caller picks `sourceId` via an overlay picker. Hotkey **Ctrl+Shift+D**, no-op when a text field has focus. Corrects audit gap #16: the recursion guard is real and sound (`resolutionEngine.ts:257-277` tracks true synchronous nesting, cap 12) — only its test is a stub.
