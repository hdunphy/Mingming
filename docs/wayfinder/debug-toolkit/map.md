# Debug & Testing Toolkit — Wayfinder Map

Label: `wayfinder:map`

**Tracker conventions (local-markdown fallback):** tickets are files in [`tickets/`](tickets/). Each carries `Type` (`wayfinder:research|prototype|grilling|task`), `Status` (`open|closed`), `Assignee` (blank = unclaimed), and `Blocked by` (links). A session claims a ticket by writing its name into `Assignee` before working. The **frontier** is every ticket that is open, unblocked (all Blocked-by closed), and unclaimed. Resolutions are recorded in the ticket's `## Resolution` section on close, and gisted below.

## Destination

A dev-build-only debug toolkit, built and working on the repo: a hidden **Debug tab** (scenario launcher + save/run editor), a **mid-battle debug overlay** (live state manipulation), **JSON scenario files** (composable by hand, exportable from a live battle, replayable), and a **headless batch-sim / balance auditor** that reuses scenario definitions — all tree-shaken out of production builds. Done when at least one real bug and one real balance question have each been driven end-to-end through the toolkit.

## Notes

- **Execution override:** unlike wayfinder's plan-only default, this map carries implementation — build tickets graduate out of the fog as design tickets resolve.
- Domain: React 19 / TypeScript / Vite / Redux Toolkit; headless engine in `src/engine`. Repo conventions: `npx vitest run` + `npx tsc -b` + `npx vite build` before shipping; never commit `package-lock.json`; git lock-sweep before device-side git commands.
- First leg: scenario launcher. UI form: Debug tab + battle overlay (both). Gating: `import.meta.env.DEV` only. Scenarios: JSON files checked into the repo at `src/debug/scenarios/{repro,balance}/<slug>.scenario.json`, with live-battle export.
- **Standing invariant (live as of [Debug gating scaffold](tickets/12-debug-gating-scaffold.md)):** nothing outside `src/debug/` may import anything inside it. `src/debug/DebugRoot.tsx` is the only edge, and `scripts/assert-no-debug.mjs` enforces it at build time.
- **Standing rule for production changes (from tickets 05, 06, 07):** when the debug layer needs something production code does not expose, add a **general-purpose** capability there and let the debug layer be its first consumer — never debug-specific code. Henry's bar: it must be something a future card, relic or game feature would plausibly use. If it fails that test, cut the verb instead.
- Key asset (from the audit): `IBattleState` is pure JSON data, the RNG seed is a plain string in state, and hooks are ID strings resolved against module registries — snapshot/replay is architecturally cheap. The main debt is creation-path nondeterminism and the total absence of dev gating.

## Decisions so far

- [Engine readiness audit](tickets/01-engine-readiness-audit.md) — Engine is snapshot-friendly (pure-JSON state, string seed threaded through reducers, registry-resolved hooks); nondeterminism is confined to battle *creation* (`Date.now`/`Math.random`/`randomUUID` in `battleFactories.ts`); `battleSlice.setBattleState` already injects arbitrary battles; **no dev gating exists anywhere** — Balance/Studio tabs and `window.runSim` ship to players today. Full findings: [research/01-engine-readiness.md](research/01-engine-readiness.md).
- [Scenario schema v1](tickets/02-scenario-schema.md) — **One** zod envelope discriminated on `kind: 'composed' | 'snapshot'` (launcher writes composed, export writes snapshot, sims re-roll seeds only on composed, replay takes either). Drift guard = int `version` + a `registryHash` content stamp over the Mingming/Program/OS registries; mismatch **warns loudly and loads anyway**. The ~9 dropped optionals are handled by one shared `normalizeBattleState()` applied at write, read, *and* diff — a fill class with real defaults, and a strip class where absence is semantically real. Files live at `src/debug/scenarios/{repro,balance}/<slug>.scenario.json`, inside `src/` so `import.meta.glob` bundles them in dev and drops them in prod.
- [Debug gating architecture](tickets/03-debug-gating-architecture.md) — Gate is `import.meta.env.DEV` wrapping a **lazy `DebugRoot`**, and `src/debug/DebugRoot.tsx` is the **single import edge** between game and toolkit, backed by a post-build `__DEBUG_TOOLKIT__` marker assertion. One `DebugRoot` is hoisted **above both App.tsx early returns** and has two presentations — floating (chip + hotkey, works at roster 0 and mid-battle) and docked (the DEV-only Debug tab) — so the early returns are never touched. Balance and Studio move in as panels; `window.runSim` survives as a one-line DEV-only import in `main.tsx`. Dispatch standardizes on `setBattleState` (dead `INITIALIZE_BATTLE` deleted); every god-tool verb is a **pure `(state, args) => IBattleState` function** under `src/debug/`, which keeps debug code out of the slices and makes the command set headlessly testable. No `debugSlice` — debug UI state lives in React context inside `DebugRoot`, so `store.ts` is never edited. Verbs append `[DEBUG]` lines to `state.logs`.
- [Live-manipulation command set](tickets/05-live-manipulation-command-set.md) — Ten v1 verbs (vitals, statuses, add-card-to-hand, set/execute intent, skip turn, insta-kill); deck stacking and AI-pause deferred. **Everything goes through the engine**: three verbs ride existing actions, five new *general-purpose* engine actions are added — which **amends 03 §4** from "no debug code in the reducer" to "no debug-*specific* code". 03's mechanism is untouched: verbs remain pure `(state, args) => IBattleState` functions under `src/debug/` applied via `setBattleState`, now delegating to `battleReducer` directly (a plain function, not a slice) so no `battleSlice` action is needed. Hooks fire **faithfully** and the caller picks `sourceId` via an overlay picker. Hotkey **Ctrl+Shift+D**, no-op when a text field has focus. Corrects audit gap #16: the recursion guard is real and sound (`resolutionEngine.ts:257-277` tracks true synchronous nesting, cap 12) — only its test is a stub.
- [Battle snapshot export](tickets/06-battle-snapshot-export.md) — Export writes `kind: 'snapshot'` **plus an optional `tape`** of dispatched actions (additive to schema v1, no version bump). The tape needs middleware, so `store.ts` gains a **general-purpose** `setActionTap(fn)` point that `DebugRoot` installs into — the same move ticket 05 made for the reducer, preserving the single import edge. Recording is always-on in DEV. Export is **zero-prompt**: overlay button plus Ctrl+Shift+E, auto-named `snapshot-t<turn>-<seed>.scenario.json`, Blob download. Import works **anywhere including mid-battle**, no confirm. Recorded limits: replay-from-start is gated on [Determinism groundwork](tickets/09-determinism-groundwork.md), and ticket 05's verbs appear in the tape as opaque `setBattleState` payloads.
- **BUILT** — [Debug gating scaffold](tickets/12-debug-gating-scaffold.md) — the DEV gate, `DebugRoot` shell (floating chip + Ctrl+Shift+D, docked Debug tab), and `scripts/assert-no-debug.mjs` are live and green on all three gates. `INITIALIZE_BATTLE` deleted. First code on this map.
- [Save/run editor verbs](tickets/07-save-run-editor-verbs.md) — Edits use existing `gameSlice` actions first; **every mutation dry-runs `PlayerSaveSchema.parse()` before dispatch** (validating after would race the autosave subscription whose silent failure is the hazard). Henry set a **stricter bar for touching production code than the ticket proposed**: a missing action qualifies only if it is a genuine game capability a future card/relic would grant. So `unlockSector` is **in** (a real hole — `unlockedSectors` is written once at save creation and never again) and `grantExperience` is **in** as its own action, but the gauntlet-stage setter is **out** (no plausible game mechanic; audit gap #20 stays open by design). `IRewardBundle.totalXP` stays unused — the deliberate "rewards grant no XP" rule at `gameSlice.ts:169-170` is a balance decision and was not reversed as a side effect of building a debug panel. No "max everything" preset.
- [Batch sim & auditor design](tickets/08-batch-sim-auditor-design.md) — `TacticalAI` plays **both sides** (a Mirror Test against `MOVES`-mode intents would not be a mirror), which needs `enemyMode: 'CARDS'` and therefore **blocks the build on [Determinism groundwork](tickets/09-determinism-groundwork.md)**. Runner is `npm run balance` → vitest with its own config matching `*.balance.ts`, so the build and `npm test` are untouched and redlines are assertions. v1 = all three §2 tests (Mirror, Archetype Gauntlet, OS Variance) with win rate / avg turns / dead-card ratio + the FTK flag; §3's stun-lock and energy-loop detection deferred as action-stream analysis. Output is a **committed, diffable** `docs/balance/balance_report.json` plus a CSV — seeded sims make it stable, so `git diff` after a card change is the balance answer. `CardStudio`'s `calculatePowerscale` is **extracted and shared** (it is half of §4's report, and the fast half); `sim/Simulator.ts` + `BalanceTester` stay but get labelled a fast approximation, not balance truth — they are stale by construction yet instant, which is the only reason live slider recompute works.
- **BUILT** — [Determinism groundwork](tickets/09-determinism-groundwork.md) — one `SeedStream` threads a single seed through every battle-creation branch; `crypto.randomUUID()` and `Math.random()` IVs are gone from `battleFactories.ts`, `sessionId` is seed-derived, and `startBattle` forwards `BattleOptions`. Audit gaps #1–#4 closed. *Save* creation is still nondeterministic → [Seeded save factories](tickets/22-seeded-save-factories.md).
- **BUILT** — [Scenario schema & normalizer](tickets/10-scenario-schema-implementation.md) — schema, registry hash, normalizer and IO under `src/debug/scenarios/`. Note the normalizer canonicalizes presence/absence but **not key order**, so replay diffs must compare structurally, never by stringify.
- **BUILT** — [Engine state actions](tickets/14-engine-state-actions.md) — five general-purpose actions with faithful hook firing. Corrects 05 section 4: `KILL_ENTITY`'s `sourceId` is required for kill credit and hook context, **not** for XP — `checkDefeat` derives receivers from the whole alive opposing party and never reads a source.
- **BUILT** — [Save reward actions](tickets/18-save-reward-actions.md) — `unlockSector` (the first mutation path `unlockedSectors` has ever had) and `grantExperience`, matching the engine level-up progression. `IRewardBundle.totalXP` still deliberately unused.
- **BUILT** — the panel wave: [Battle debug overlay](tickets/15-battle-debug-overlay.md), [Snapshot export & import](tickets/16-snapshot-export-import.md), [Action tape](tickets/17-action-tape.md) and [Save/run editor panel](tickets/19-save-run-editor-panel.md). Five panels now register in `src/debug/panels/index.ts`; `DebugRoot` installs the action tap and the Ctrl+Shift+E hotkey. **`DebugRoot` mounts twice** (floating layer + docked tab), so anything global it installs must be refcounted — both hooks are.
- **Measured payoff of the gate:** production bundle went 613 modules / 732.17 kB JS / 55.62 kB CSS → 605 / 705.81 kB / 43.41 kB once Balance and Studio moved behind it. ~26 kB JS and ~12 kB CSS no longer ship to players. A direct `grep` of `dist/` for every debug identifier returns nothing, independent of the marker assertion.
