# Mingming Work System: tracker + orchestrator (design, ruled 2026-10-03)

Source: Henry's design session. Full doc with the diagram: https://claude.ai/code/artifact/63bf5b6e-ab5c-4136-92e2-f9a596a9e88e
Every line below is ruled. Do not redesign it; ask Henry (ask_henry) only where it is silent.

## Rulings
1. Areas: marketing (includes demos and playtest releases), art (Art & Assets), ui, engine, balance (Balance & Card Design).
2. Bugs and feedback are not an area: they land in an Inbox, get sorted into an area and tagged type: bug.
3. Tickets live as files in the repo (`docs/wayfinder/<milestone>/tickets/`), each with a YAML header.
4. Henry sees the work on a page generated by a script from the headers, published as one private claude.ai page that replaces "Wayfinder Open Items".
5. Wayfinder maps stay as milestones (goal + "done when"); every ticket also carries an area.
6. Inbox triage: the orchestrator proposes area, milestone and type; Henry confirms in a batch.
7. Henry closes tickets. Agents may close bug tickets only if: they added a test that failed before the fix and passes after, the full suite is green, and the change stayed inside the files the ticket names. Agent-closed bugs appear in the daily digest.
8. Convert open tickets only (~30); closed tickets stay as history.
9. Parallel work: a design agent groups a ticket's rows into lanes by the files they touch (rows touching the same file share a lane); each lane runs on its own worktree branch off the ticket branch; an integrator merges lanes into the ticket branch and runs the full suite. Rows that will not split cleanly become smaller tickets under the same milestone.
10. What reaches Henry: direction and look, scope, design changes a player would notice, anything hard to undo. Everything else goes in a daily digest (8 pm) he can overrule.
11. Branches: lane -> ticket branch -> milestone branch (e.g. `first-impressions`); Henry merges milestones into `main` and does every push.
12. Budgets: the first 2 weeks only report token spend per area; budgets are set from those numbers.
13. Ticket numbers stay global and continue from 191; rows keep their letters.

## Ticket header
```yaml
---
id: 191
title: Halve Sun Devourer
area: balance          # marketing | art | ui | engine | balance
type: bug              # bug | feature | polish | research | chore
milestone: first-impressions
status: ruled          # inbox | designing | ruled | in-progress | built | closed | blocked | parked
blockedBy: [189]
needsHenry: []         # open questions, one line each
rows:
  - { id: a, title: Halve the stack bonus, status: built, lane: 1 }
  - { id: b, title: Update card text, status: ruled, lane: 1 }
---
```
The body below the header stays free-form (rulings, spec, results). A check script refuses unknown areas, statuses, types or milestones.

| Status | Means | Set by |
| --- | --- | --- |
| inbox | raw note, bug report or feedback, unsorted | anyone |
| designing | being worked out by a design agent or with Henry | orchestrator |
| ruled | all decisions made, ready to build | Henry (approval) |
| in-progress | an implementer is on it | orchestrator |
| built | every row built, tests pass | implementer |
| closed | done | Henry; agents for bugs only (rule 7) |
| blocked | waits on a ticket or on Henry | anyone |
| parked | kept for later on Henry's say | Henry |

## Tracker page (top to bottom)
1. Needs Henry: open decisions, tickets awaiting approval, built tickets to close, Inbox items to confirm.
2. By milestone: goal, "done when", open tickets in frontier order; a switch to group by area.
3. Running now: agents and what they work on; token spend per area this week.
4. Daily digest: small calls agents made; bugs agents closed.
5. Recently closed.
Clicking a ticket shows its full file. The page only shows state; Henry acts through the orchestrator.

## Roles
| Role | Model | Does | Never |
| --- | --- | --- | --- |
| Orchestrator | Opus | plans, triages, starts agents, reviews results, republishes the page | writes code, designs in detail |
| Researcher | Sonnet | collects references into a short report with pictures | decides |
| Designer | Opus or Fable | prototypes, asks framed questions, writes tickets, splits rows into lanes | edits game code |
| Writer | Sonnet | drafts devlogs, posts, store copy for approval | posts anything |
| Implementer | Sonnet | builds one lane in its own worktree | pushes, changes design beyond the spec |
| Integrator | Sonnet | merges lanes, runs tests, settles mechanical conflicts | picks between two designs |

## Build plan (in order; each piece usable on its own)
1. Ticket header schema + `npm run tickets:check`; one Sonnet pass adds headers to the open tickets.
2. `npm run tracker`: generates the tracker HTML from the headers; the orchestrator publishes it as the claude.ai page "Mingming Tracker". "Wayfinder Open Items" retires.
3. Orchestrator reads/writes the repo: load tickets from files; status changes written back to headers as commits.
4. Lanes + integrator.
5. Inbox + triage.
6. Decision line, daily digest, budgets.
7. Researcher and writer agents; screenshots on visual decisions.
8. `/handoff` for one-off tickets.
9. Away-mode guide.
Pieces 3-9 are changes to Henry's Claude Code mods (the agent-orchestrator plugin), not to the game; they get tickets like any other work.
